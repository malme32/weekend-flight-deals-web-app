# Weekend Flight Deals

A small static web page that lists **cheap Ryanair weekend round trips from
Athens (ATH)**: fly out on a **Friday**, return the following **Monday**, total
round trip **≤ €100**.

The page is plain HTML/CSS/ES modules with no build step and no runtime
third-party calls. It reads a committed snapshot from `data/deals.json`, which a
dev-time Node script generates from Ryanair's keyless fare-finder API.

Live target: <https://github.com/malme32/weekend-flight-deals-web-app>

## Rules (v1)

- Origin defaults to **ATH** (selectable).
- Outbound leg must depart on a **Friday**; the return leg must depart on the
  **following Monday** (3 nights).
- The **total** outbound + inbound price must be **≤ €100** (EUR).
- Only Ryanair fares are considered.
- Results are sorted by total price, cheapest first.

## Quick start

Serve the repository root statically (no build step):

```sh
python3 -m http.server 8000
# open http://localhost:8000/
```

`npm start` runs the same static server.

## Tests

Node.js >= 18, using the built-in test runner:

```sh
node --test test/
# or
npm test
```

`src/core/*` is pure and DOM-free, so the logic runs under Node. `src/ui/*` and
`src/main.js` are the only DOM-coupled modules.

## Refreshing the data snapshot

`data/deals.json` is generated by [`scripts/fetch-deals.mjs`](scripts/fetch-deals.mjs),
which queries the keyless endpoint
`https://www.ryanair.com/api/farfnd/v4/roundTripFares` for the next weekends and
applies the Friday/Monday and price rules:

```sh
node scripts/fetch-deals.mjs --origin ATH --weekends 4 --max 100
# or
npm run fetch
```

Supported flags: `--origin`, `--weekends`, `--max`, `--market`, `--reference`
(defaults to today), `--out`. Commit the resulting `data/deals.json` so the
static site stays in sync.

> Prices are a point-in-time snapshot and are not live. The runtime page never
> calls Ryanair; only the dev-time script does.

## Deploying to GitHub Pages

1. Push `main` to `malme32/weekend-flight-deals-web-app`.
2. In **Settings → Pages**, set **Source** to *Deploy from a branch* and choose
   branch **`main`**, folder **`/ (root)`**.
3. The site is served at `https://malme32.github.io/weekend-flight-deals-web-app/`.

All asset and data paths are relative, so the app works from a project subpath.

## Project layout

```
index.html                 # search/results page
src/
  main.js                  # bootstrap: load data, wire filters, render
  core/                    # pure, DOM-free, unit-tested
    weekend.js             # upcoming Fri/Mon pairs, weekend keys
    deals.js               # normalise raw fares -> Deal[]
    filter.js              # filter + sort + URL query state
    format.js              # EUR and date/time formatting
  ui/
    render.js              # DOM rendering of results + empty state
    filters.js             # filter controls <-> URL state
  styles.css
data/
  deals.json               # committed snapshot (generated)
scripts/
  fetch-deals.mjs          # dev-time snapshot generator
test/                      # node:test suites
```

## Data model

```json
{
  "generatedAt": "2026-09-20T08:36:49.215Z",
  "currency": "EUR",
  "origin": "ATH",
  "weekends": ["2026-09-25", "2026-10-02"],
  "deals": [
    {
      "origin": "ATH",
      "destination": "CFU",
      "originName": "Athens",
      "destinationName": "Corfu",
      "weekendKey": "2026-09-25",
      "outbound": { "date": "2026-09-25", "departureTime": "07:25", "arrivalTime": "08:30", "flightNumber": "FR4298", "price": 30.08 },
      "inbound":  { "date": "2026-09-28", "departureTime": "19:10", "arrivalTime": "20:15", "flightNumber": "FR4299", "price": 25.13 },
      "totalPrice": 55.21
    }
  ]
}
```

Filter state is reflected in the URL, e.g.
`?origin=ATH&weekend=2026-09-25&max=100&q=corfu`, and restored on reload.

## Acceptance criteria

1. Only deals with outbound **Friday**, inbound **following Monday** and
   `totalPrice ≤ 100` EUR are rendered.
2. Origin defaults to **ATH**; the origin selector changes results.
3. Max-price filter (default €100) and destination search work; results sorted
   by total ascending.
4. Filter state is encoded in the URL and restored on reload.
5. Each deal shows route, city names, dates, times, flight numbers, per-leg and
   total EUR price.
6. No runtime third-party network calls; only same-origin `data/deals.json`.
7. `node --test test/` passes on Node 18 and `src/core/*` is DOM-free.
8. The site works served statically from GitHub Pages using relative paths.
9. This README documents local run, tests and data refresh.
